The Studio **Insight** tab is the human review step in the agentic
workflow pipeline. It surfaces pending BPMN proposals generated by the
Insight Engine and routes your decision (approve or reject) back through
`POST /api/v1/insight/proposals/{id}/review`.

<Aside type="note">
  A proposal is a candidate change to a deployed workflow (for example, a
  retired node, a new error handler, a relaxed SLA on a service task). It
  is **not** a draft — proposals have been validated against the BPMN
  support matrix, so the question is whether you want the change applied
  to a running process, not whether the change is well-formed.
</Aside>

## What you see

The tab opens with a two-column layout:

- **Left** — list of proposals with status chips (`PENDING`, `APPROVED`,
  `REJECTED`, `APPLIED`). Each card carries the project, the proposal
  author (the agent), the workflow and activity under review, and a
  short rationale.
- **Right** — a diff view of the proposal against the current BPMN
  source, with the structured `proposedSource` payload. Approve and
  Reject buttons sit at the bottom.

## Review a proposal

<Steps>

1. Pick a card on the left. The right pane loads the proposal detail.

2. Read the diff and the agent's rationale. The `expectedUpdatedAt`
   token in the corner is the optimistic-locking handle — keep an eye on
   it; if a newer proposal lands while you read, the buttons disable
   until you refresh.

3. Optionally add a comment in the reviewer note box. Comments are
   stored alongside the decision and surfaced in the project audit
   trail.

4. Click **Approve** or **Reject**. Studio calls `InsightAPI.reviewProposal`
   with the matching `expectedUpdatedAt`, then refreshes the card to its
   new status.

5. The card leaves the *Pending* filter the moment the response returns.
   Use the status chips to switch back and audit your past decisions.

</Steps>

## Approve vs. apply

- **Approve** — records your decision and forwards the proposal to the
  project's BPMN redeployment queue. The next deploy snapshot picks it up.
- **Reject** — closes the proposal. The originating agent receives the
  rejection comment as a structured response and uses it as a negative
  feedback signal in its next iteration.

There is no manual "apply" step; approval is the commit boundary.

## Authorization

The Insight tab is visible to any user that the engine has authenticated.
Proposal review additionally requires the `abada-insight-reviewer`
membership on the **project** under review (engine-side authority), so
read-only colleagues cannot accidentally approve a change.

## Limitations

- The Insight Engine does not yet auto-merge parallel proposals. Two
  reviewers approving the same workflow at the same time will see one
  conflict; resolve by re-applying the latest view.
- Diff rendering is text-based for the `proposedSource` payload. Visual
  model diffing (node relabelling, lane layout) is on the next release.
- Audit history is recorded server-side; a dedicated audit UI for
  proposal decisions is deferred (see
  [`studio-app-spec.md`](../../../../../docs/development/studio-app-spec.md)).
