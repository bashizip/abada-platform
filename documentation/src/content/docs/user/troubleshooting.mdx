---
title: Troubleshooting
description: Diagnose preflight, identity, runtime configuration and telemetry failures.
---

Start with configuration and service state:

```bash
./release/abada-platform doctor dev --no-pull
./release/abada-platform status dev
./release/abada-platform logs dev
```

| Symptom | Check |
| --- | --- |
| Production config exits immediately | Replace every required placeholder in `.env.prod`; validate DNS, CORS and OIDC URLs |
| Port 80/443 already used | Stop the conflicting service or move Abada to a dedicated host |
| `no matching manifest for linux/arm64/v8` with `1.0.0-rc.1` | Use the current repository launcher; it detects the immutable amd64-only RC.1 images and enables Docker compatibility mode |
| Tenda/Orun shows configuration error | Inspect the generated `/config.js`; all four runtime values are mandatory and URLs must be HTTP(S) |
| Login loops | Match redirect URI, web origin, issuer, realm and client ID exactly |
| Engine unhealthy | Check PostgreSQL health and engine logs; telemetry must not be the cause |
| No Grafana data | Confirm the telemetry overlay is present, then inspect Collector, Alloy and Grafana containers |
| Workflow succeeds while collector is down | Expected: telemetry export is best-effort and independent of workflow correctness |

Render the merged configuration without starting anything:

```bash
docker compose --env-file .env.prod \
  -f compose.yaml -f compose.prod.yaml config
```

Do not post `.env.prod`, JWTs, authorization headers or full sensitive payloads
in support reports. Include exact image versions, Compose version, health
output, redacted logs and the command that failed.
