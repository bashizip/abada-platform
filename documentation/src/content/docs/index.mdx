## Agents advise, rules decide, humans approve, PostgreSQL remembers

Abada runs business processes in which AI does real work under rules you can
audit:

- **APL is the process language.** Studio draws `abada.io/v1` YAML as a
  diagram, and the engine compiles it directly into the executable graph.
  BPMN 2.0 files import and run on the same engine, extended with Abada's
  agent and review steps.
- **The engine enforces the contract.** Every agent answer is checked against
  its schema and confidence threshold before it enters the process; rules and
  decision tables run deterministically inside the transaction.
- **Real process shapes.** Steps can repeat with a limit, route around
  errors, timeouts and weak AI answers, wait for a human decision with a
  required comment, escalate when late, and fall back to another model when a
  provider is rate-limited.
- **Evidence for every decision.** Each agent attempt, decision and route is
  in the audit trail — without prompts, secrets or comment text.

## Release status

These guides describe the current `dev` tree.

- **`1.1.0-rc.1`** is the current evaluation release candidate (milestone
  M2, real process shapes): one APL contract served by the engine, durable
  execution tokens, bounded loops, error and timeout routes, enforced service
  levels, model fallback, review outcomes with a required comment, incidents
  you can retry from Studio, and Studio editing for all of them. See the
  [release notes](https://github.com/bashizip/abada-platform/blob/dev/docs/release-notes/1.1.0-rc.1-release-notes.md).
- **`1.0.0-rc.8`** remains available. PostgreSQL is the source of truth, API v1
  and worker protocol v1 are frozen, and native APL and the BPMN subset are
  certified runtime surfaces.

The authoritative gates live in the [roadmap and
contracts](/reference/contracts/).
