# Abada 1.1.1 release notes

Patch release of [1.1.0](1.1.0-release-notes.md), prepared 2026-10-16
(gate report [`1.1.1-gate-report-2026-10-16.md`](../development/1.1.1-gate-report-2026-10-16.md)).
It fixes two defects found by a clean-machine install of 1.1.0 and changes
nothing else: no new feature, no migration, no API or worker protocol change.
Upgrade the engine, Studio and the agent worker together, as usual.

## Fixes

- **A user's first sign-in no longer returns 500.** Studio sends several
  requests at once after sign-in; each recorded the user (the principal) in its
  own transaction, so on the very first sign-in all but one failed on
  `uq_principal_issuer_subject`. The losing request now retries once in a new
  transaction and finds the row the other one created. Covered by
  `PostgresPrincipalFirstSightTest` (eight concurrent first sights on
  PostgreSQL resolve to one principal; the test fails on 1.1.0).
- **The one-line installer finishes under `curl … | bash`.** Bash read the
  installer from the pipe while it ran, and `docker compose exec` during
  `up dev` consumed the rest of it: the installer exited 0 without printing
  bob's account, the missing-key hint or the manage commands. The script is now
  parsed as one block and `up dev` reads `/dev/null`. The missing-key hint says
  that agent steps need a key and names `ABADA_LLM_GEMINI_API_KEY`. The
  distribution contract test now pipes the installer into bash with a launcher
  that reads stdin.

## Upgrade

No schema change: Flyway stays at `V38`. Pull the `1.1.1` images (or set
`ABADA_VERSION=1.1.1` for the installer) and restart. Rolling back to 1.1.0 is
an image change only.

## Known limitations

Unchanged from [1.1.0](1.1.0-release-notes.md#known-limitations).
