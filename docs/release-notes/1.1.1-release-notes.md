# Abada 1.1.1 release notes

Release of 2026-10-16 on top of [1.1.0](1.1.0-release-notes.md) (gate report
[`1.1.1-gate-report-2026-10-16.md`](../development/1.1.1-gate-report-2026-10-16.md)).
It fixes two defects found by a clean-machine install of 1.1.0 and makes AI
providers live: a key is tested before it is saved, models are read from each
provider, prices come from a public catalog when you have not set one, and
Studio updates everywhere as soon as a provider works. REST API v1 and worker
protocol v1 stay backward compatible: new endpoints and one new error code.
Flyway applies `V39`, additive. Upgrade the engine, Studio and the agent
worker together.

## Fixes

- **A user's first sign-in no longer returns 500.** Studio sends several
  requests at once after sign-in; each recorded the user (the principal) in its
  own transaction, so on the very first sign-in all but one failed on
  `uq_principal_issuer_subject`. The losing request now retries once in a new
  transaction and finds the row the other one created
  (`PostgresPrincipalFirstSightTest`; it fails on 1.1.0).
- **The one-line installer finishes under `curl … | bash`.** `docker compose
  exec` during `up dev` consumed the rest of the piped script, so the installer
  exited 0 without printing bob's account, the missing-key hint or the manage
  commands. The script is parsed as one block and `up dev` reads `/dev/null`;
  the distribution contract test pipes the installer into bash.
- **Settings → Insight Engine** showed "Not configured" after a key was saved
  in the AI Providers tab, until the panel was reopened. It reads the provider
  again whenever the tab is opened or a provider changes.

## AI providers are tested before they are saved

Saving a provider that changes its key, base URL, default model or type makes
one short call first, outside any transaction. If the provider does not
answer, nothing is saved: `PUT /v1/ai-providers/{id}` and
`PUT /v1/insight/config/ai` return `422 AI_PROVIDER_TEST_FAILED` with the
provider's reason (a key in it is masked). Disabling a provider, or saving one
with no key anywhere, needs no test. Studio's button is **Test & save**.

## Models come from each provider

After a save, once a day and on demand, the engine reads each provider's own
model list with its key (`GET /v1/ai-providers/models`,
`POST /v1/ai-providers/{id}/models/refresh`). A model a provider lists and that
routes to it is allowed for agent nodes, fallback models and model retries in
addition to `ABADA_AGENT_ALLOWED_MODELS`, and the designer offers it, so a new
model can be used the day its provider publishes it.
`ABADA_MODEL_DISCOVERY_ENABLED=false` keeps the allow-list strict.

## Prices: yours, else the public catalog

The engine still prices every call itself, with the price in effect at the
time of the call. Without a price of yours, it now uses the public model
catalog (OpenRouter's model list by default, read once a day with a plain
`GET`; `ABADA_PRICE_CATALOG_URL`, `ABADA_PRICE_CATALOG_ENABLED`), then the
snapshot shipped with the release (367 models, read 2026-10-16). Your price
always wins. A catalog change is a new row from the time it was read, never an
edit. Settings → Model Prices shows each model's price and its source (your
price, public catalog, release snapshot, unpriced), with a search and a button
to set your own (`GET /v1/model-prices/effective`, `GET /v1/model-prices/catalog`,
`POST /v1/model-prices/catalog/refresh`). Catalog prices are those the catalog
publishes, not read from each provider's own page: set yours for a negotiated
rate.

## Studio follows provider changes everywhere

When a provider is saved, removed, made the default or its models refreshed,
every view that shows provider state updates at once, in the same tab and in
other Studio tabs of the browser: the Insight panel's "LLM Not Configured"
badge, Settings → Insight Engine, a Deploy & Start or Dry Run warning about a
missing provider, and the allowed models of the designer.

## Privacy

The running platform still never contacts Abada. It reaches only what you
configure or enable: your model providers (agent calls, a test call on save,
their model list daily), your MCP tool servers, your identity provider, your
telemetry collector if on, and the public price catalog (daily, on by default,
switchable off). See the [privacy page](https://docs.abadaplatform.com/user/privacy/).

## Upgrade

Back up first and keep `ABADA_ENCRYPTION_KEY`. Flyway applies `V39`
(`model_catalog_prices`, `ai_provider_models`, `ai_refresh_state`); no existing
row changes. Providers saved before 1.1.1 keep working; they are tested the
next time their key, URL or model changes. Pull the `1.1.1` images (or set
`ABADA_VERSION=1.1.1` for the installer) and restart.

## Rollback

Rolling the images back to 1.1.0 is possible without a restore: 1.1.0 ignores
the `V39` tables, and prices of your own are unchanged. Costs computed with
catalog prices while on 1.1.1 stay as recorded.

## Known limitations

- Catalog prices may differ from a provider's own list price or your contract.
- A provider whose `/models` endpoint is unavailable keeps the allow-list and
  its last good list; the read error is shown in Settings.
- The rest is unchanged from [1.1.0](1.1.0-release-notes.md#known-limitations).
