## Context

Abada is transitioning from BPMN-compiled execution to a fully native,
self-optimizing APL (Abada Process Language) runtime with enterprise
governance. This plan covers the product and architecture execution for that
transition: studio UI/UX surfaces first, then the post-transpilation engine
core.

Execution proceeds phase by phase. Each phase must preserve the BPMN runtime
contracts and verification expectations recorded in `AGENTS.md` and the 1.1
roadmap before the next phase starts.

---

## Part 1 — Studio UI/UX

### Task 1.1: Format badge & file metadata indicator

- [ ] Add visual format pills in the header and process list (`.apl.yaml` vs
  `.bpmn`).
- [ ] Display runtime status tags on open files (e.g., `[APL Native]` vs
  `[BPMN Imported]`).
- [ ] Update canvas header metadata to show the active language spec version
  (`abada.io/v1`).

### Task 1.2: Native DMN rule inspector widget

- [ ] Update the right-side Inspector panel for `decision-table` / `DMN` nodes.
- [ ] Build a matrix editor component supporting:
  - Input variable mappings (`name` + `${...}` expressions).
  - Ordered rules with `when` conditions and typed `then` outputs
    (`string` | `number` | `boolean`).
  - Hit Policy selector narrowed to `FIRST | UNIQUE | COLLECT`.
  - Explicit `otherwise` fallback row toggle.
- [ ] Ensure bidirectional sync between the matrix UI and canonical APL YAML
  (`normalizeTableInputs` / `resolveRuleOutcome`).

### Task 1.3: AI optimization visual diff layer ("AI Diff")

- [ ] Create a canvas visual overlay mode for proposed workflow
  modifications.
- [ ] Render added nodes/edges in green highlight and removed or modified
  paths in red/amber.
- [ ] Add inline comment tooltip rendering for YAML annotations generated by
  the optimization engine.

## Part 2 — Post-Transpilation Core

### Phase 1: Native APL persistence (engine core)

- [ ] **Database migration:** update the PostgreSQL schema with a
  `schema_type` column (`BPMN_XML` vs `APL_NATIVE`) and immutable versioning
  tables.
- [ ] **Runtime graph compiler:** build an internal engine
  bytecode/JSON graph representation generated directly from raw APL YAML.
- [ ] **Polymorphic definition loader:** enable `AbadaEngine` to load and
  execute native APL definitions directly alongside legacy compiled BPMN XML.

### Phase 2: Continuous optimization engine (the Insight Loop)

- [ ] **OpenTelemetry trace analyzer:** build an asynchronous worker to
  process engine OTel spans, flagging agent nodes with high failure rates,
  token latency, or fallback loops.
- [ ] **Automated APL PR generator:** implement an LLM worker that drafts
  optimized APL YAML patches, embedding explanatory `#` comments directly
  above updated nodes or DMN rules.

### Phase 3: Governance & multi-human approval workflows

- [ ] **Governance engine:** implement serial and parallel multi-stakeholder
  approval gates (e.g., Tech Lead + Compliance Officer sign-offs) before an
  AI-proposed APL patch goes live.
- [ ] **Versioning & rollback:** implement an atomic, one-click rollback
  mechanism to prior APL definition revisions in PostgreSQL.

### Phase 4: Studio live simulation & token visualizer

- [ ] **Canvas token traversal:** animate real-time token movement across
  canvas nodes during execution runs in the Run panel.
- [ ] **Variable state inspector:** render real-time top-level instance
  variable mutations after each node evaluation (probabilistic agent outputs
  vs deterministic in-transaction DMN outputs).

---

## Execution order

1. Part 1 Studio surfaces (format badges, DMN inspector, AI diff).
2. Phase 1 native APL persistence and loader.
3. Phase 2 Insight Loop with the ADR-003 telemetry pipeline.
4. Phase 3 governance gates and rollback.
5. Phase 4 live simulation and token visualizer.

Each completed phase requires the related contract documentation updates and
tests described in `AGENTS.md` verification expectations.
