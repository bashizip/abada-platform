# Abada 1.1.2 publication gate report — 2026-10-17

Release of 2026-10-17 on top of `1.1.1`. Scope: the one-line installer only
([release notes](../release-notes/1.1.2-release-notes.md)). The engine,
Studio, agent worker, API, worker protocol and schema (`V39`) are the code of
`1.1.1`; only their version number changes.

## Finding

Running the public installer (`curl -fsSL https://install.abadaplatform.com/install.sh | bash`)
from a directory that held an earlier installation downloaded and verified
the `1.1.1` archive, then started the `1.0.0-rc.3` images pinned by the
existing `.env.dev`, which the installer kept untouched. On a database already
at `V39` that engine would not start. The run was stopped before the rc.3
engine and Studio containers started; the schema was checked at `V39`.

| Fix | Evidence |
| --- | --- |
| On an existing `.env.dev` the installer backs it up, sets the release's image tags, appends new settings, keeps the rest and says it is updating | `verify-install-distribution.sh` update case (old rc.3 tags, an operator password, an unknown operator setting): fails on the 1.1.1 script, passes |

## After publication (required)

The finding came from the public installer, so the release is accepted only
after the public installer, once republished by the tag workflow, updates an
existing installation to `1.1.2` on this machine.

**Done 2026-10-17.** PR #204 merged as `097c9e7`, tag `v1.1.2`, tag workflow
green (four images, archive and checksum, install Worker, GitHub release);
`https://install.abadaplatform.com/latest` answers `1.1.2`. Then, from the
repository root of the release owner's machine, over the existing `1.1.1`
installation in `./abada-platform`, the public command
`curl -fsSL https://install.abadaplatform.com/install.sh | bash` (with
`ABADA_USAGE_PING=0`, which only skips the report) exited 0 and printed:

```
[info]  Updating the existing installation in …/abada-platform from 1.1.1 to 1.1.2.
[info]  Your settings are kept; the previous file is saved as …/.env.dev.backup-20261017-054842.
[ok]    Abada 1.1.2 is running.
  HIGH review: bob / bob
  Gemini key: not set. Agent steps need a model key: …
```

`.env.dev` then pinned the four `1.1.2` images, every container ran a `1.1.2`
image and was healthy, and `GET /api/v1/info` answered `"version": "1.1.2"`.
The release is accepted.
