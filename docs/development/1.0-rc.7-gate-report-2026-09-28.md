# Abada 1.0.0-rc.7 publication gate report — 2026-09-28

## Decision

**Pending release-owner sign-off — `1.0.0-rc.7` evaluation release
candidate.** Local verification is complete and green. The candidate is not
yet merged into `dev`, tagged or published.

`1.0.0-rc.7` is a Studio and packaging candidate on top of `1.0.0-rc.6`. The
engine runtime, Flyway schema (`V21`), REST API v1 and worker protocol v1 are
unchanged; engine, SDK and agent-worker changes are version strings only. See
`docs/release-notes/1.0.0-rc.7-release-notes.md`.

The tag workflow is part of the gate. A failure in image publication,
multi-platform manifests, archive publication, anonymous image access,
clean-runner installation or `/latest` promotion returns this decision to
**NO-GO**.

This candidate keeps the evaluation scope of the 1.0 RC line (see
`1.0-rc-publication-gates.md`, rc.1 and rc.5 scope sections): public-cloud
TLS/external-OIDC certification, multi-host failover, rolling upgrades,
production backup/restore, live telemetry certification, Windows quickstart
CI, image attestations and independent security review remain deferred and
are not claimed here.

## Scope

Every change on `main` since `v1.0.0-rc.6` (`07b3c71`) is included. Each was
evaluated; none touches the engine, schema or public contracts, so none needed
to be held back.

| Area | Included | Why it is worth shipping |
| --- | --- | --- |
| Studio canvas | BPMN shapes, ELK auto-layout, saved positions respected, minimap, alignment guides, shortcuts (`f68f4a8`, `5e144f1`) | Processes read as BPMN and keep the author's layout |
| Studio fixes | Edge arrows (`20b5025`), inclusive fork branches drawn and saved (`d0db0fc`), outcome routes lit only when taken (`e629b09`), clean-checkout build (`68bf2e5`) | The fork fix prevented saving from the canvas from dropping rules; the build fix makes a clean Studio image build possible |
| Self-hosting | Inter bundled, no Google Fonts requests (`1694e2e`) | Sovereign deployments make no third-party calls from Studio |
| Dev login | Studio-styled Keycloak theme (`87c81ef`, `f04e1e6`, `272e2ea`), applied to existing dev realms (`2213cbd`) | Shipped in the archive; development realm only |
| Brand | Abada mark in Studio and docs (`a5fb320`, `2e2a972`, `fbcd85c`) | Replaces the Vite template logo |
| Packaging | `LICENSE` in the archive and all four images (`79be36b`) | Closes the gap recorded in the rc.6 gate report |

Website, site CI and showcase-recording commits are on the same branch but are
not release artifacts; the site is deployed separately and its
`RELEASE_VERSION` moves to rc.7 only after the tag workflow succeeds.

## Findings fixed during verification

- **Licence text missing from artifacts** (open item from rc.6): the archive
  and all four images now ship `LICENSE`. The engine and docs images moved to
  the repository-root build context; every build invocation (CI, publish
  workflow, `scripts/dev/up.sh`, `scripts/dev/rebuild.sh`,
  `scripts/prod/build-prod.sh`, `AGENTS.md`) is updated and the deployment
  contract test enforces it.
- **Stale Studio build command** in `studio-app-spec.md` used the `studio/`
  context, which cannot build since Studio's image needs the engine parser
  source; corrected to the repository root.

## Non-blocking warnings

- Studio: 14 lint warnings (unused symbols) and a production chunk above
  500 kB.
- Documentation: Starlight notes an empty `i18n` collection.
- Verification host had about 7 GiB free disk; builds ran sequentially to
  avoid the ENOSPC seen during rc.6 verification.
