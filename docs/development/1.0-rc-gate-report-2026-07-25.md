## Remediation applied

### Backend tracing and security tests

- `TraceLogContext` now treats missing, invalid and no-op spans safely.
- Scope close order and MDC restoration preserve an existing trace and span.
- Tests cover prior MDC restoration and a missing span.
- `SecurityAuthorizationContractTest` uses a deterministic mocked
  `JwtDecoder`, issuer and audience so its authorization assertions execute
  without remote OIDC discovery.

Result:

```text

Failures: 0
Errors: 0
Skipped: 0
```

The verification includes PostgreSQL Testcontainers persistence, migrations,
restart recovery, atomic commands, idempotency, external work, cluster
acquisition and security contracts. The packaged Spring Boot JAR started in
the development profile on an ephemeral port before being terminated.

### Frontend dependency remediation

React Router had no audit-clean published version: older releases remained
covered by multiple XSS, redirect, CSRF and deserialization advisories, while
the newest release was covered by the RSC CSRF advisory. Both Tenda and Orun
now use a small client-side router limited to the features the applications
actually require: history navigation, route matching, parameters, redirects
and internal links. No SSR, data-router, RSC or server-action surface is
included.

Tenda also moves to the ESLint 10-compatible lint dependency line. Two newly
introduced advisory-style React Hooks rules are explicitly disabled to retain
the existing lint contract; the established Rules of Hooks checks remain
enabled.

Results:

| Tenda | 0 vulnerabilities | PASS; 12 Fast Refresh warnings | PASS |
| Orun | 0 vulnerabilities | No lint script exists | PASS; chunk-size warning |

### Jaeger named-volume ownership

The bundled telemetry failure was caused by Jaeger running as UID `10001`
without write access to `/badger/key`. The telemetry overlay now includes a
one-shot, networkless initialization service that creates the Badger
directories and assigns them to UID/GID `10001` before Jaeger starts.

The deployment contract asserts:

- the initializer is present only with bundled telemetry;
- it has no network;
- it runs as root only for the ownership operation;
- Jaeger waits for successful completion;
- the exact ownership target is tested.

The static contract passes. Live verification remains mandatory because the
local Docker registry pull stalled before Alloy and the other telemetry images
were available.

## Publication conditions and deferred debt

Publication conditions:

1. Commit and push only the intended RC changes.
2. Create `v1.0.0-rc.1` from `dev`.
3. Require the tag workflow to build the exact engine, Tenda and Orun images,
   rebuild the archive and publish the GitHub release.

Deferred 1.1 infrastructure debt:

- live telemetry-disabled, bundled and external-OTLP cloud deployments;
- public TLS, external OIDC and multi-host failure testing;
- production backup/restore and rolling upgrades;
- Windows quickstart CI, image attestations/scanning and independent review.

## Publication decision

Create `v1.0.0-rc.1` and publish it as a normal GitHub **release** after the
intended changes are committed and pushed. If the exact tag workflow fails,
the decision returns to **NO-GO** until the failure is fixed. The release must
retain its evaluation-only limitation and must not claim public-cloud
production certification.

Post-publication manifest inspection found that the original engine, Tenda and
Orun tags contain `linux/amd64` only. The immutable tags were not rewritten.
The repository launcher supplies an explicit Docker compatibility mode for
those exact images on ARM64 hosts, and the publication workflow now rejects
subsequent release images unless their manifest includes `linux/amd64` and
`linux/arm64`.
