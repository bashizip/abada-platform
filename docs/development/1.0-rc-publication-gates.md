# Abada 1.0 RC Publication Gates

This is the release-blocking sign-off checklist for every Abada 1.0 release
candidate. The roadmap defines what must exist; this document defines the
evidence that must be collected for the exact commit, images and archive being
published.

An unchecked item means **NO-GO** unless a candidate-specific scope exception
below explicitly defers that item, records the limitation in the release notes
and deployment matrix, and is approved by the release owner. Evidence from an
older commit or image tag does not satisfy a new candidate.

## `1.0.0-rc.1` evaluation release-candidate scope

On 2026-07-26 the release owner approved publishing `1.0.0-rc.1` as an
evaluation release candidate on the validated Docker Compose baseline. It is
a normal published GitHub release, not a GitHub prerelease, and it does not
claim public-cloud production certification.

For this candidate, repository integrity, backend/PostgreSQL correctness,
frontend builds and audits, security contract tests, Compose/preflight
validation, the executable JAR, the checksummed archive and documentation
build are release-blocking. The following evidence is deferred to the
[1.1 RC infrastructure track](../archive/roadmap-to-1.1.0-rc.md):

- public reference-host TLS and external-OIDC deployment;
- multi-host failure and production rolling upgrades;
- live bundled/external telemetry certification and outage drills;
- cloud backup/restore and external exposure scans;
- Windows quickstart CI, image attestations and independent security review;
- separate engineering, security, operations and documentation sign-offs.

Deferred items remain unsupported claims and must not be described as passed.
This exception does not apply to a stable 1.0 release or a production-certified
1.1 release.

The original `1.0.0-rc.1` image manifests were subsequently found to contain
only `linux/amd64`. They remain immutable. The repository launcher supplies an
explicit ARM64 compatibility mode for those exact tags, and every subsequent
candidate must pass the native dual-platform manifest gate below.

## `1.0.0-rc.5` test-user evaluation scope

Published 2026-09-03. This candidate ships Studio, Engine, Docs and Agent
Worker containers for test users to evaluate the platform. The retired Tenda
and Orun apps have been removed; Studio is the sole operator UI.

Key improvements over rc.4:
- Gemini AI provider with model selector in Settings
- Insight Engine enabled by default in dev stack
- Agent nodes default to the configured AI model
- Improved auto-layout with edge-crossing and overlap avoidance
- Persistent layout locking for running instances
- Node selection reliability in canvas
- Dependabot security fixes (browserslist, fast-uri, @humanfs/node)

The following items are deferred from the full publication-gate checklist
for this test-user evaluation candidate:

- Telemetry is deactivated by default on the dev profile; live telemetry
  certification is deferred to 1.1.
- Production reference-host deployment with external OIDC and TLS is deferred
  to 1.1.
- Windows quickstart CI is deferred to 1.1.
- Independent security review is deferred to 1.1.
- Performance benchmarks are deferred to 1.1.
- Backup/restore and rolling-upgrade production evidence is deferred to 1.1.
- User guide publication waits for live deployment command verification.

  1.0-RC changes.
