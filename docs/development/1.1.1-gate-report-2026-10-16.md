# Abada 1.1.1 publication gate report — 2026-10-16

Release of 2026-10-16 on top of `1.1.0`. Release notes:
[`1.1.1-release-notes.md`](../release-notes/1.1.1-release-notes.md).

Scope, in two parts:

1. Two defects found by a clean-machine install of the published `1.1.0` (all
   Abada containers, volumes and images removed, then the public
   `curl -fsSL https://install.abadaplatform.com/install.sh | bash` with no
   model key).
2. Live AI providers, requested by the release owner after that install: a key
   is tested before it is saved, models are read from each provider, prices
   come from a public catalog when no administrator price exists, and Studio
   updates everywhere when a provider changes. This adds migration `V39`, five
   endpoints and one error code, all additive.

| Settings → Insight Engine showed "Not configured" after a key was saved, until the panel was reopened | The tab reloads on open and on provider changes; Studio-wide change events | `AiProvidersSettings.test.tsx`, `aiProviderEvents.test.ts`; live screenshot on the 1.1.1 build |

## Addendum: refresh-lease race found by CI on the release PR

CI on PR #203 (`0fba3a4`) failed `PostgresPriceCatalogTest`: 3 of 6 concurrent
first claims of a refresh lease succeeded. The first claim created the lease
row with `save()`, which merges; when another replica had just committed the
row, the merge overwrote its `claimed_until`. The row is now persisted, so a
concurrent first claim fails on the primary key and reports not claimed
(`9086a8a`). The test now races 16 claims on 60 new leases; it fails on the
previous code (2 claims on one lease) and passes on the fix. No schema change.
