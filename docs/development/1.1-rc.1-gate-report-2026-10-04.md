# Abada 1.1.0-rc.1 publication gate report — 2026-10-04

## Decision

**GO — `1.1.0-rc.1` evaluation release candidate. Published 2026-10-04.**
Every local gate below passed on the version-bump commit. The release owner
requested publication on 2026-10-04. The candidate merged into `main` as
[#166](https://github.com/bashizip/abada-platform/pull/166) at `e4ead3e`
(identical tree to the verified `b46be77`), where the image build and the
website deployment passed, and `v1.1.0-rc.1` is tagged on that commit. The
[tag workflow](https://github.com/bashizip/abada-platform/actions/runs/37232079132)
succeeded: four multi-platform images, the verified public archive, the
[GitHub release](https://github.com/bashizip/abada-platform/releases/tag/v1.1.0-rc.1)
and `/latest` at `1.1.0-rc.1`.

`1.1.0-rc.1` closes milestone M2 *Real process shapes*. It adds Flyway `V23`
to `V26` (execution tokens, incidents, per-token loop counts, boundaries and
service levels) and additive endpoints (`GET /v1/apl/schema`,
`POST /v1/apl/validate`, task decisions, incidents and their retry with a
model override). REST API v1 and worker protocol v1 stay backward compatible;
the SDK and the attempt metadata change is additive (`requestedModel`). See
`docs/release-notes/1.1.0-rc.1-release-notes.md`.

The evaluation scope of the RC line is unchanged (see
`1.0-rc-publication-gates.md`): public-cloud TLS/external-OIDC certification,
multi-host failover, rolling upgrades, production backup/restore drills, live
telemetry certification, Windows quickstart CI, image attestations and an
independent security review remain deferred and are not claimed here.

## Scope

Every change merged into `dev` since `v1.0.0-rc.8`:

| Area | Included | Why it is worth shipping |
| --- | --- | --- |
| E1 One APL contract | Engine-owned JSON Schema, `/v1/apl/schema`, `/v1/apl/validate`, Studio types generated from it, typed `metadata.variables` | Studio and engine could disagree on what a valid process is |
| E2 Execution tokens | `V23` `process_tokens`; joins count token ids; waiting work names its token | A branch ending early could block its join; same-command join arrivals were dropped |
| E3 Bounded loops | Cycles only with `loop.max_iterations`; `on_exhausted` or a `LOOP_EXHAUSTED` incident (`V24`, `V25`); BPMN cycles bounded too | APL refused every cycle and BPMN could loop forever |
| E4 Boundaries | `on_error`, `on_timeout`, enforced `sla_hours` with `escalate_to`, `fallback_models`, rate-limit deferral, operator retry on another model (`V26`) | Failed or slow work stalled silently; a rate-limited model blocked the process |
| E5 Review outcomes | `outcomes` with required comments; decision endpoint; `review_comment` reaches the next step | The rework loop (agent drafts, human rejects with a reason, agent revises) |
| E6 Studio editing | Connect menu, edge delete, route editors, loop and issue badges | E3–E5 were only editable in YAML |
| Operations | Incident list and retry (with model override) in Studio; Dry Run kept across layout-only edits | Operators needed the API to unblock an instance |
| Reliability | Daily dependency audit; images published from `main` and tags only; Jackson bump | Recurring audit failures; images were published before promotion |
| Documentation | End-to-end tutorial with 23 screenshots, reorganized user guide, link-checked build, fixes found while writing it | The guide no longer matched the product |

## Exit demo

M2's exit demo is a rework loop — agent drafts, human rejects with a comment,
agent revises, human approves — that survives an engine stop mid-loop.

- `AplReviewRuntimeTest.aRejectionCommentReachesTheNextDraftAndAnApprovalEndsTheLoopAcrossARestart`
  (PostgreSQL Testcontainers) rejects a draft with a comment, **stops the
  engine** between the rejection and the revised draft, starts a new engine on
  the same database, checks that the next draft receives the comment, approves
  it and completes the instance; history records the outcome and the comment
  length, never the text. The stop is an application-context shutdown, not a
  process kill; state is database-authoritative in both cases, and lease
  expiry for a killed worker is covered by `AgentWorkerResilienceTest`.
- Documentation tutorial on 2026-10-04 (isolated engine JAR with an H2 file
  database, Studio, the Agent Worker and a deterministic OpenAI-compatible
  test model): the full flow in Studio as alice (author) and bob (reviewer),
  including a rejection with comment, a revised draft at `draft_iteration` 2
  and approval; a fallback to `gpt-5-mini` on a simulated HTTP 429; an engine
  restart while an instance waited at its review, which then completed. The
  run found the defects fixed under *Fixes found while writing the
  end-to-end tutorial* in the release notes.
