# Abada 1.0.0-rc.6 publication gate report — 2026-09-23

## Decision

**NO-GO (pending) — `1.0.0-rc.6` evaluation release candidate.**

Local verification of the M1 "truth and safety" candidate is complete and
green, but three release-blocking items are open (see
[Open items](#open-items)): the M1 exit demo, the merge of the candidate into
`dev`, and release owner sign-off. The decision changes to **GO conditional on
the exact tag workflow** only when all three are closed and recorded here.

This candidate keeps the evaluation scope of the 1.0 RC line (see
`1.0-rc-publication-gates.md`, rc.1 and rc.5 scope sections): public-cloud
TLS/external-OIDC certification, multi-host failover, rolling upgrades,
production backup/restore, live telemetry certification, Windows quickstart
CI, image attestations and independent security review remain deferred and
are not claimed here.

## Findings fixed during verification

- **Documentation dependency advisories** (critical Astro RCE
  GHSA-26w7-cxv4-gfx2 and GHSA-376h-93r7-7g6f; high js-yaml GHSA-2883-xcg3-v3hh;
  moderate devalue GHSA-9rgm-9g3h-6x36): Astro 7.3.4, js-yaml 4.3.2 (`3079f52`).
- **Studio test-tooling advisory** (moderate, GHSA-82fw-gwwq-j7x9): Vitest 5
  (`206ad9d`).
- **Flaky agent-worker test** assumed port 54321 was unused; it now uses a
  closed ephemeral port (`290c71b`).
- **Product identity:** `/api/v1/info` and OpenAPI described Abada as a
  "high-performance" BPMN 2.0 workflow engine. Now APL-first;
  `engine.standard` value changed, shape unchanged, noted in the release notes
  (`e32c4fe`).
- **Site claims:** removed "process improves itself", "autonomous agents",
  an unbounded "without losing state" and "both are BPMN-based"; the claims
  checker now rejects them. The site version was reverted to the published
  rc.5.

## Non-blocking warnings

- Studio: 24 lint warnings (unused symbols, Fast Refresh) and a large
  production chunk.
- Documentation: large Mermaid/Vite chunk; Starlight notes an empty `i18n`
  collection and the missing generated entry for the `docs -> 404` item.
- Verification environment: parallel runs briefly exhausted host disk space
  (ENOSPC) and Docker Desktop later became unresponsive and restarted. The
  crash left a corrupted `grafana/alloy` base layer in the local containerd
  store that survived `rmi`, restart and re-pull; `docker system prune -af`
  cleared it. Every affected check, including the four local images, was
  re-run sequentially afterwards; results above are from the re-runs.

## Publication condition

Create and push `v1.0.0-rc.6` only from the reviewed merge commit in `dev`,
after the open items are closed and this report records **GO**. The tag
workflow must publish all four multi-architecture images, verify anonymous
manifests, publish the archive and checksum, run the public installer on a
clean runner and promote `/latest` last. Any failure returns the decision to
**NO-GO**.
