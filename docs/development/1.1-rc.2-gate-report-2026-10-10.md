# Abada 1.1.0-rc.2 publication gate report — 2026-10-10

## Decision

**GO — `1.1.0-rc.2` evaluation release candidate, requested by the release
owner on 2026-10-10.** For this candidate every build, test and artifact ran
on GitHub Actions; nothing was built on a local host. The tag workflow
evidence is recorded under *Candidate record* once it completes.

`1.1.0-rc.2` closes milestone M3 *Agents that act*. It adds Flyway `V27` to
`V33` (all additive) and additive endpoints (tool credentials, agent steps,
step payloads, evidence policy, model prices, the project event stream). REST
API v1 and worker protocol v1 stay backward compatible; the SDK changes are
additive. See `docs/release-notes/1.1.0-rc.2-release-notes.md`.

The evaluation scope of the RC line is unchanged (see
`1.0-rc-publication-gates.md`): public-cloud TLS/external-OIDC certification,
multi-host failover, rolling upgrades, production backup/restore drills, live
telemetry certification, Windows quickstart CI, image attestations and an
independent security review remain deferred and are not claimed here.

**Exceptions accepted by the release owner for this candidate:**

- The roadmap's combined M3 exit demo (two engine replicas, a worker kill and
  a replica kill in one scripted run) was not run as one demo. Each of its
  steps is evidenced separately below.
- No local JAR, image or archive was built: the CI build and the tag workflow
  are the artifact evidence.
- The public reference host was not upgraded as part of this gate.

## Scope

Every change merged into `dev` since `v1.1.0-rc.1`:

| Area | Included | Why it is worth shipping |
| --- | --- | --- |
| E7 Tool servers | `TOOL_SERVER` resources, per-tool policies, deploy-time resolution and frozen bindings, tool credentials (`V27`) | Agents could only name tools the platform did not govern |
| E8 Tool loop | Multi-turn MCP tool calling in the worker; `max_turns`, `max_tokens_total`, `budget_usd` | Agents could not act |
| E9 Step journal | `agent_steps` (`V28`), write-ahead journaling, stable idempotency keys, `OUTCOME_UNKNOWN` incidents | A crash could repeat a write or pay for a model turn twice |
| E10 Tool approvals | `TOOL_APPROVAL` tasks (`V31`), approve/reject with comment, approver groups, SLA | Writes that move money need a person |
| E11 Evidence and cost | Evidence policy, encrypted payloads, retention, model prices, engine-computed cost (`V30`) | Auditable decisions and bounded spend |
| E12 Live Studio | Project event stream (`V33`), Live indicator, agent-step inspector, designer editors for every M3 field | Operators polled and could not see agent steps |
| E13 Routing agents | `routes` with engine-checked choice and `when` veto | Agents could not choose the next step safely |
| E20 Composition | `call-process` (`V29`), agent delegation (`V32`), lineage | Sub-cases needed their own governed processes |
| Fixes | Confirmed unknown outcomes resume the agent; approvers kept; reuse ignores call ids; the stream opens at once; explorer dialogs; npm advisories | Found while writing the agent tutorial and by the dependency audit |
| Documentation | Concepts, Use cases, Tutorial: an agent that acts (13 screenshots), architecture pages, examples and `ExampleGalleryTest` | M3 had reference contracts but no visible user documentation |

## Exit demo

M3's exit demo: an agent uses MCP read tools, proposes an approval-required
write and a person approves it; a crash does not repeat the write; cost per
instance is visible; a triage agent delegates a sub-case to a governed child
process, the parent resumes with its result and the lineage is visible. It was
not run as one scripted demo on two replicas; the evidence for each step:

| Step | Evidence |
| --- | --- |
| Read tools, journaled with cost | Agent tutorial run (below): `payments/get_order` journaled with tokens and cost in the step inspector. `AgentToolLoopEndToEndTest` (worker over real HTTP to a stub model and stub MCP server). |
| Approval-required write, approval task with the arguments | Tutorial: bob (task group `finance`) approved `payments/refund` with its arguments and digest. `PostgresToolApprovalTest`, `ToolApprovalApiTest`. |
| A crash does not repeat the write | Tutorial: the stub server applied the refund and failed before answering; the engine marked it `OUTCOME_UNKNOWN`, opened an incident and never re-sent it; after **It happened** the agent completed on the same attempt; the stub recorded one refund per run. `AgentToolLoopEndToEndTest` (keyed write, server crash after applying it: one effect), `PostgresAgentStepJournalTest` (keyed write across a lost lease and an engine restart takes effect once; unkeyed interrupted write; reuse across attempts), `PostgresToolApprovalTest` (approved unkeyed write confirmed by an operator, a later attempt with a new call id is neither approved nor sent again). |
| Cost per instance | Tutorial: 5 steps, 3,840 tokens, 0.0017 USD at the configured price. `PostgresEvidenceAndCostTest`. |
| Delegation, parent resumes, lineage | `PostgresAgentDelegationTest` (child started from a delegation, declared outputs only, the agent completes; restarts while the child runs and before the resume give one child and one result), `PostgresCallProcessCrashTest` (restart after the child starts and between its end and the resume, with the job leased by a crashed replica; two replicas at once), `ExampleGalleryTest` (support triage routes, delegates and calls a governed child). Lineage in Studio: `LineagePanel.test.tsx` (not exercised in a browser for this gate). |
