# Abada 1.0.0-rc.8 publication gate report — 2026-10-01

## Decision

**Pending release-owner sign-off — local verification is green.** Every
local gate below passed on the version-bump commit. The decision becomes
**GO** when the release owner signs off, the candidate merges into `dev`
with Java CI and the image build green, and the tag workflow publishes the
images, archive and `/latest`. A failure in image publication,
multi-platform manifests, archive publication, anonymous image access,
clean-runner installation or `/latest` promotion makes it **NO-GO**.

`1.0.0-rc.8` is a fix release on top of `1.0.0-rc.7`. It adds Flyway `V22`
(`ai_providers`) and additive endpoints (`/v1/ai-providers/**`,
`GET /v1/workers/me/ai-credentials`, `GET /v1/projects/{projectId}/jobs/{jobId}/error`);
REST API v1 and worker protocol v1 stay backward compatible, and the SDK
change is additive. See `docs/release-notes/1.0.0-rc.8-release-notes.md`.

This candidate keeps the evaluation scope of the 1.0 RC line (see
`1.0-rc-publication-gates.md`): public-cloud TLS/external-OIDC
certification, multi-host failover, rolling upgrades, production
backup/restore, live telemetry certification, Windows quickstart CI, image
attestations and independent security review remain deferred and are not
claimed here.

## Scope

Every change merged into `dev` since `v1.0.0-rc.7`:

| Area | Included | Why it is worth shipping |
| --- | --- | --- |
| Agent worker | Startup registration retry with bounded backoff (#149) | The worker survives a host reboot instead of being restarted by Docker until the engine is ready (9 restarts on the demo VM) |
| AI providers | Studio-saved keys serve agents, Insight and authoring; several named providers; worker credentials endpoint; `V22` (#151); clear default model and key status in Studio (#154) | A key saved in Studio never reached the agent worker in rc.7, so agent tasks failed while the start gate passed |
| Security | `ABADA_ENCRYPTION_KEY` passed to the engine, generated by `up server`, required by production preflight; dev-key ciphertext re-encrypted (#151) | Studio keys were encrypted with the engine's public development key on every install |
| Error details | Redacted stack traces from the worker, job error endpoint, Studio details dialog (#152) | Operators saw only an exception class name |
| Studio | Undo/redo for the open process (#153) | Requested capability |
| Documentation | dompurify and fast-uri advisories patched (#155) | Unblocked the documentation audit gate |
